## 1. 训练目标究竟是什么

一句话编码成 token 序列 x₁,…,xₙ，自回归模型定义：

`p(x₁,…,xₙ) = ∏ pθ(xₜ | x₁,…,xₜ₋₁)`。

最大化训练文本概率等价于最小化平均负对数似然。假设窗口为 `[11, 7, 23, 5]`，输入可以取 `[11,7,23]`，目标取 `[7,23,5]`。一次前向同时预测三个位置，但每个位置只能看见它之前的内容。训练不需要人工给每个词打标签，标签来自原文本右移一位，这就是自监督。

模型输出 logits `[B,T,V]`，logits 是未归一化分数。对每个位置沿 V 做 softmax，得到所有候选下一个 token 的概率。正确答案概率为 p 时，loss 为 `-log p`：从 0.1 提高到 0.5，loss 从约 2.303 降到约 0.693。

验证 perplexity=`exp(平均 token loss)`。它描述模型在该分词和数据分布上的平均不确定性；换了 tokenizer 后每个 token 含的信息量改变，per-token loss 不能直接横向比较。

## 2. 为什么先做 byte BPE

字符词表可能很大，也难覆盖所有 Unicode；纯字节词表只有 256 项且能覆盖任意 UTF-8，但一个常见单词需要很多 token。BPE 用训练数据发现常见的连续字节组合，在覆盖能力和序列长度之间折中。

训练的基本步骤：

1. 初始化 256 个单字节 token 与特殊 token。
2. 先把特殊标记隔离，再用 GPT-2 风格正则划分预分词单元。
3. 在每个单元内部统计相邻 token 对出现次数。
4. 找最高频 pair，加入合并后的新 token，在所有受影响单元中替换。
5. 维护新的 pair 频率，直到达到目标词表大小或没有 pair。

例如有 `low` 出现 5 次、`lower` 出现 2 次。初始 `l,o,w` 和 `l,o,w,e,r` 都包含 `(l,o)`、`(o,w)`，所以这两对各计 7 次，而不是各计 2 次。**单元出现次数必须加权**。若第一步合并 `(l,o)`，下一步候选包含 `(lo,w)`；合并次序本身构成编码规则。

预分词不是可有可无的加速细节：它约束 BPE 合并边界。特殊 token 必须保持原子性，不应该把 `<|endoftext|>` 与附近正文合并，也不能把它的内部字节当普通训练 pair。

仓库用 `Counter` 先统计完整单元的字节串，减少重复构造 Python 字节对象；然后才把不同单元拆成字节 tuple。`owners[pair]` 记录含有这个 pair 的单元索引，合并时只访问受影响单元。堆中保留旧计数的条目，取出时检查是否过期，这叫惰性失效。

```python
# 等价核心写法，略去 owners/heap 的增量维护
for word, frequency in word_counts.items():
    for pair, count in Counter(zip(word, word[1:])).items():
        pair_counts[pair] += count * frequency
best = max(pair_counts, key=lambda pair: (pair_counts[pair], pair))
```

这里相同频率选择字典序最大的字节 pair，是作业要求的确定性规则。随意使用 Counter 的插入顺序会得到不同 merges，进而导致 tokenizer 测试失败。

编码时不重新按频率选择 pair，而是根据训练得到的合并 rank，反复执行当前可用的最早合并。解码先拼回完整字节流，再 UTF-8 解码：一个汉字可能跨多个 token，不能逐 token 先独立解码再拼接。

词表用 Base64 保存字节，解决任意 byte 不能直接可靠放入 JSON 字符串的问题。`encode_iterable` 把每个传入元素视作完整段落或行；任意字节位置截断文本后分别编码，不保证与完整文本编码一致。

## 3. 数据集划分与磁盘 token 文件

本次准备流程见 [prepare_formal_a1.py](../scripts/prepare_formal_a1.py)：

1. 下载固定来源版本的完整 TinyStories train/valid，校验训练源 SHA256，记录验证源摘要与来源。
2. 以 `<|endoftext|>` 为完整文档边界，规范文档外围空白；计算验证文档 SHA256，从训练中排除完全相同文档。
3. **只在训练文本上学习 BPE**。验证集不能影响词表选择。
4. 用同一个 tokenizer 编码两个 split，保存 `uint16` 数组和元数据。
5. 记录源文件、处理后文本、词表和二进制 token 文件的摘要。

V=10,000 小于 65,536，token ID 可用 uint16，每个 token 2 字节。训练取批时再转换为 PyTorch long。`np.memmap` 将数组映射进虚拟内存，无需一次把所有 token 复制进 Python 列表。

采样起点 s 后，`x=data[s:s+T]`，`y=data[s+1:s+T+1]`。必须保证数据至少有 T+1 个 token。我们的训练按随机窗口有放回采样，累计 token 数不等于“严格无重复地遍历多少个 epoch”。EOS 告诉模型故事结束，但当前普通因果掩码不阻止下一个故事注意前一个故事；这是明确的数据打包约定。

当前编码器逐行调用 encode 并保留换行，这是记录在元数据中的分段协议；它不是任意切块都等价于整文件编码的声明。分词器必须与训练 checkpoint 配套保存，不能拿不同词表生成文本。

## 4. 沿着一次前向逐层检查形状

本次架构 V=10,000、T=256、d=512、L=4、H=16、f=1344，单头维度 dh=32。

| 步骤 | 张量形状 | 对应参数 |
|---|---|---|
| token ID | `[B,T]` | 无 |
| embedding | `[B,T,512]` | `[10000,512]` |
| Q、K、V 投影 | 各 `[B,T,512]` | 各 `[512,512]` |
| 分头 | `[B,16,T,32]` | reshape，无新参数 |
| attention scores | `[B,16,T,T]` | 动态激活 |
| attention 输出合头 | `[B,T,512]` | 再乘输出投影 |
| SwiGLU 中间层 | `[B,T,1344]` | 三个线性映射 |
| lm_head | `[B,T,10000]` | `[10000,512]` |

本实现 Linear 存 weight `[d_out,d_in]`，所以使用 `x @ weight.T`；Embedding 是按 ID 查行，不是做 one-hot 矩阵乘法。所有主要线性层没有 bias，embedding 与输出 head **不共享权重**。

## 5. RMSNorm、RoPE、Attention 与 SwiGLU

RMSNorm：`y = x / sqrt(mean(x²)+eps) * g`。只沿隐藏维归一化，不跨 batch、时间位置。`g` 是可学习的 d 维缩放参数。仓库先转 FP32 计算平方、均值和倒数平方根，再转换回输入 dtype，减小低精度累计误差。它与 LayerNorm 的区别是没有减去均值。

RoPE 对 q、k 的相邻偶奇维做二维旋转。第 i 对维度的角频率是 `theta^(-2i/dh)`，位置 p 的角度为 p×频率：

```python
# 实际实现的核心
even, odd = x[..., 0::2].float(), x[..., 1::2].float()
rotated = torch.stack((even*cos - odd*sin,
                       even*sin + odd*cos), -1).flatten(-2)
```

对 q 和 k 用同一频率体系，内积能反映相对位置差。不能把整个隐藏向量的位置维与头维弄反；head dimension 必须是偶数。仓库注册 `inv_freq` 为 buffer，随模型移动设备，但不把它当可训练参数。

Attention 公式：`S=QKᵀ/√dh`，`P=softmax(S+mask)`，`O=PV`。因果 mask 允许 j≤i；未来位置在 softmax 前设置为负无穷，softmax 后概率为 0。**在 softmax 之后才把未来概率清零但不重归一化，会改变输出尺度。**

除以 √dh 是为了控制点积随维度增加时的方差，避免 softmax 过早饱和。稳定 softmax 先减每一行最大值，不改变概率，但减少 exp 溢出。

```python
# 仓库的朴素注意力核心
scores = (q @ k.transpose(-1, -2)) / math.sqrt(q.shape[-1])
scores = scores.masked_fill(~mask, float('-inf'))
out = softmax(scores, -1) @ v
```

朴素实现保留 T×T 激活，这正是 A2 要优化的对象；A1 当前正式基线仍用手写注意力，并没有自动接入自写 Triton kernel。

SwiGLU：`FFN(x)=W₂[SiLU(W₁x) ⊙ W₃x]`，其中 `SiLU(z)=z·sigmoid(z)`。一个分支提供经过非线性的门，另一个分支提供被调制的值。总参数约 3df，所以 f 取约 8d/3 时，与普通 4d 宽、两矩阵的 FFN 计算量接近。1344 是兼顾这个比例与 64 对齐的具体值。

Pre-norm block：

```python
x = x + attention(norm1(x))
x = x + ffn(norm2(x))
```

残差连接为梯度提供直接通路；pre-norm 让进入每个子层的尺度更稳定。最后再做一次 RMSNorm 和 lm_head。post-norm、去 norm、去 RoPE、SiLU FFN 是仓库已有消融选项，比较它们时需要保持 token 预算和数据不变。

## 6. 交叉熵如何传回梯度

代码使用 `logsumexp(logits) - logits[target]`，没有先显式算概率再 log，避免小概率下溢。每个位置对 logits 的导数是 `softmax(logits)-one_hot(target)`：正确项得到提高分数的方向，其他项按当前概率被压低。

loss 在 B×T 位置求平均，梯度通过输出 head、四个 block 回到 embedding。虽然标签只监督下一个 token，attention 让损失能够影响上下文中参与预测的表示。

因果性检验：固定前缀，任意改变未来 token，比较前缀位置的 logits，必须不变。只看训练 loss 不足以发现未来信息泄漏；泄漏模型会出现异常低 loss，却无法正确自回归生成。

## 7. AdamW、学习率与梯度累积

Adam 保存一阶矩 m 和二阶矩 v：

`mₜ=β₁mₜ₋₁+(1-β₁)gₜ`，`vₜ=β₂vₜ₋₁+(1-β₂)gₜ²`。

仓库按课程公式计算 `alpha=lr*sqrt(1-β₂ᵗ)/(1-β₁ᵗ)`，然后 `p -= alpha*m/(sqrt(v)+eps)`，再执行衰减 `p *= (1-lr*weight_decay)`。这里 eps 加在未校正二阶矩的平方根上，且衰减的执行顺序是这份实现的明确约定；不能假定与任意库 AdamW 在所有边界上逐位一致。

weight decay 是独立缩放参数，不是简单把 L2 项加入梯度后再由 Adam 自适应缩放。本 A1 实现把所有参数放入同一衰减组；A4 官方参考训练另有 norm 不衰减的分组，两者不要混用。

warmup 从小学习率开始，减少刚初始化时过大更新；随后余弦衰减到 min_lr。恢复时必须使用原 `steps` 总计划计算学习率。中断在 800 步后恢复，不能把余弦调度重新从 0 开始。

正式配置 microbatch128，accumulation2，全局 batch256，单步 token=65,536。两次 forward/backward 的 loss 各除以 2，梯度相加后只做一次 optimizer.step：

```python
optimizer.zero_grad(set_to_none=True)
for _ in range(accum):
    loss = cross_entropy(model(x), y) / accum
    loss.backward()
gradient_clipping(model.parameters(), 1.0)
optimizer.step()
```

不要在每个 microbatch 后清梯度；也不要不除 accum，导致有效学习率放大。全局范数裁剪先求所有参数梯度平方和再统一缩放，不能对每层独立裁剪却声称等价。

BF16 autocast 减少部分矩阵运算和激活的存储，**参数、梯度和 Adam 矩仍为 FP32**。本实现通常不需要 FP16 式 GradScaler。仅参数、梯度、两份 Adam 状态的近似静态下界为 16N 字节，不是 2N。

## 8. 本轮参数量、预算与运行步骤

参数量公式（SwiGLU、无 bias、untied embedding）：

`N=2Vd + L(4d²+3df+2d) + d = 22,696,448`。

一个显存手算例子：microbatch128时，FP32的`[128,256,10000]`logits约1.22GiB；单层BF16的`[128,16,256,256]`注意力矩阵约0.25GiB。反向还需保存相关激活与中间结果，不能只加一个scores矩阵就结束。本次正式形状短跑峰值allocated约13.44GiB，而16N静态参数/梯度/Adam项只有约0.34GiB，说明这里主要消耗是激活与loss相关张量。小模型不等于任意batch都便宜。

## 10. 生成与消融实验

生成每次取最后一个位置 logits，按 temperature 调整后采样一个 token，追加到上下文。temperature=0 走 greedy；top-p 保留累计概率达到 p 的最小高概率集合并重新归一化。当前 A1 生成脚本没有 KV cache，会重复计算窗口，适合教学与短输出，不是生产级推理引擎。

```bash
.venv/bin/python scripts/generate.py \
  --checkpoint runs/formal/a1-tinystories-seed42/checkpoint.pt \
  --tokenizer data/tinystories/tokenizer.json \
  --prompt 'Once upon a time' --temperature 0.8 --top-p 0.95 --seed 42
```

正式基线跑完之后，再建立独立目录比较不同学习率、norm 位置、RoPE 与 FFN。一次只改变一个因素，固定 token 总量，至少记录 loss–token 和 loss–walltime 两张曲线。调学习率时，不应只挑早期下降最快而后期发散的配置。

自检练习：手算 B=1,T=3,V=4 的 CE 与梯度；手写因果不变性测试；在固定一个 batch 上过拟合；在第 17 步中断并续跑到第 30 步，与连续训练对照；解释把 T 从 256 改为 512 时哪些存储项翻倍、哪些变四倍。
