## 原理与关键实现详解

对应 [官方 A3](https://github.com/stanford-cs336/assignment3-scaling)。代码：[fit.py](../src/cs336_scaling_lab/fit.py)、[fit_remaining_scaling.py](../scripts/fit_remaining_scaling.py)。

## 1. 想回答的决策问题

假设有一笔固定训练预算，要把它用来训练“较大模型、较少数据”，还是“较小模型、更多数据”？A3 用一组小规模受控实验，估计预算约束下验证 loss 最小的 N 和 D。

缩放规律是经验关系，不是保证所有模型、数据、上下文和训练阶段都适用的物理定律。它的作用是减少盲目大训练，而不是用一条好看的直线替代对实验范围的判断。

需要先区分三种预算：理论 FLOPs、某种硬件上的运行时间、费用。2026 官方 API 使用特定 B200 硬件时间协议；自有 PRO 6000 上按 6ND 设计的本地实验是独立研究，不能假称已经消耗或完成官方 API 预算。

## 2. 资源计数：为什么常见 C≈6ND

对于 dense Transformer 中以参数矩阵乘为主的训练，一次 forward 约2N FLOPs/token，backward 约再4N，于是近似6N。训练 D 个 token 就约6ND。

它略去 attention 的额外序列长度项、embedding/非线性细节、重算、优化器、验证、padding 和通信。长上下文、小模型、带重算训练时偏差会更明显。所以我们记录 `estimated_flops`，而不是把它伪装成精确 GPU 硬件计数。

给定预算 C 和模型量 N，token 数取 `D=C/(6N)`。若每步处理 K 个 token，则 `steps=floor(D/K)`。步数是整数，真实计算量往往略小于名义预算；如果为了避免太少步而强行至少训练3步，还可能超过名义预算，必须在 manifest 中检查。

例子：C=6×10¹⁵，N=10⁸，则 D=10⁷；若每步65,536 token，需要约152步。把模型增大到2×10⁸，在相同预算下只能训练约76步。若 warmup 固定200步，两个模型都尚未完成热身，结论就主要反映 warmup 设计，而非合理训练后的规模关系。

## 3. IsoFLOPs 曲线如何建立

选多个计算预算 C₁,C₂,…；在每个预算内扫描一系列模型大小 N，给每个模型分配对应 D。固定数据来源、分词器、上下文、目标函数和可比较的优化设置，记录每次完成后的验证 loss。

| 固定量 | 扫描量 | 计算得到 | 测量量 |
|---|---|---|---|
| 预算 C、数据和验证协议 | 模型参数 N | D 与训练 steps | 最终验证 loss |

每个 C 形成一条 loss–N 曲线。理想情况下，过小模型受容量限制，过大模型因 token 不足而欠训练，中间存在最优区。只测两个大小很难确定最低点；如果最低点总在最左或最右边，应扩展扫描范围。

公平不一定等于所有模型学习率完全相同。较大模型可能需要不同最优 LR，但如果只给某个模型充分调参、其他模型随便训练，比较也不公平。应事先定义每个规模的调参预算和规则。

## 4. 从最优点得到幂律

记每个预算内观测到的离散最低点为 N*(C)，假设：

`N*(C)=k_N Cᵃ`，`D*(C)=k_D Cᵇ`。

取对数后为线性关系：`log N*=log k_N+a log C`。仓库核心：

```python
# fit_isoflops 的实际逻辑节选
minima = [min(rows, key=lambda row: row['final_loss'])
          for _, rows in sorted(groups.items())]
c = np.array([float(row['compute_budget']) for row in minima])
n = np.array([float(row['parameters']) for row in minima])
d = c / (6*n)
a, log_kn = np.polyfit(np.log(c), np.log(n), 1)
b, log_kd = np.polyfit(np.log(c), np.log(d), 1)
```

注意这是拟合**观测到的离散最低点**，没有在每条曲线上凭空插值出未训练的最佳模型。只要 D 严格由 C/(6N) 定义，就应有 a+b≈1、`6k_N k_D≈1`。这是有用的不变量测试。

若 a=0.5、b=0.5，预算增4倍意味着最佳参数和 token 都约增2倍；若 a=0.7、b=0.3，参数增得更快。不要脱离数据就直接套用某个熟悉的指数。

## 5. 联合拟合 loss 曲面

另一种模型是 `L(N,D)=E+A N^(-α)+B D^(-β)`：E 是不可约项，另两项分别表示有限模型容量和有限数据带来的损失。

仓库 `fit_loss_surface` 将 E/A/B/α/β 用 exp 参数化保证为正，用 log loss 残差和 robust least squares 拟合，并尝试多个初始点。非线性优化有局部解和可辨识性问题；少量狭窄范围数据可能允许完全不同的参数组合都拟合得很好。

在固定 C 下代入 D=C/(6N)，理论最优点满足：

`α A N^(-α) = β B (6N/C)^β`。

因此 `N*∝C^(β/(α+β))`，`D*∝C^(α/(α+β))`。这个推导建立在该 loss 模型确实适用、约束正确和没有其他瓶颈的前提上。

联合拟合利用所有测量点，但也引入更多结构假设。IsoFLOPs 拟合直观但对网格、边界点和噪声敏感。应该把两者当成可互相诊断的工具，而不是任选一条漂亮曲线。

## 6. 本地研究的边界

本仓库只发布实测本地训练与拟合实现，不发布未运行的官方API脚本或合成fixture。最小两个预算的最佳规模位于扫描边界，应补做更小模型与更多seed再外推。

## 8. 如何让一次 scaling 研究可审查

保存每个模型的精确参数量和形状、tokenizer、实际训练 token、学习率曲线、失败任务、训练秒数、验证集合与评测时间。把预算取整偏差画出来，检查候选是否真正接近同一个 C。

至少留出一个较大预算作为预测验证：先不用它拟合，预测其最佳规模区间，再真实训练附近若干点。如果预测误差很大，应回头检查 regime、数据重复、batch size 或优化器差异，而不是只继续扩大模型。

不确定性可来自随机种子重复、bootstrap 或明确的网格范围；没有这些证据时，应报告“候选范围内的最好观测”，不要给出小数点很多位的最优参数数量。

练习：自行构造 a=0.4 的合成最低点并恢复指数；手算预算取整偏差；画出边界最优造成的错误外推；推导联合 loss 的最优分配；解释为什么 tokenizer 改变后旧 scaling fit 可能失效。
